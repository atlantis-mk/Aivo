# Add composer resource mentions

## Problem or goal

Users need a quick way to reference an existing project and discover globally enabled Skills, built-in tools, installed extensions, and configured MCP sources while writing a task. A selected reference must reach Core as structured intent so the conversation receives the corresponding project binding, Skill instructions, or eligible tool capabilities instead of relying on visible prompt text alone. Globally disabled resources are excluded, while each enabled extension or MCP server appears once without expanding its contributed tools in the chooser.

## Expected behavior

Typing `@` at a word boundary opens a fuzzy-searchable local picker grouped into local actions plus project, Skill, extension, MCP, and tool sections. The local group offers one “选择文件或文件夹” action that directly opens one native file-or-directory chooser without an intermediate type confirmation. The composer `+` button invokes the same action. A selected file enters the existing attachment and model-capability validation flow, while a selected directory enters the existing project-context flow. Files and directories dropped onto the workspace use the same routing: every accepted file enters the attachment flow and the first accepted directory enters the single project-context slot; additional directories are explicitly refused. The action consumes the active query without creating a typed resource reference. The project group contains existing selectable projects and identifies and orders the current project first. Empty sections are hidden. Selecting a resource consumes the active query, renders an icon-and-name resource tag inside the composer editing region, and records a bounded typed reference for submission; duplicate resources collapse to one tag, selecting another project replaces the draft project tag, and ordinary text that merely resembles a mention has no binding effect. Tags can be removed directly or with Backspace from an empty text input. Arrow keys, Enter, Escape, click, and ordinary typing are supported. Enter confirms a result or local action while the picker is open and otherwise submits the message; Shift+Enter always inserts a newline.

On immediate submission Core validates every selected ID against current authoritative state before appending the user event. An exact project reference uses the existing immutable session association contract; a new conversation is created in the referenced project, an unscoped conversation may bind once, and a conflicting existing binding is refused. Enabled Skills and globally eligible built-in tools are merged into that conversation's manual activation. An enabled extension or MCP source remains one reference but Core expands it to only that source's currently registered, globally eligible tools. Core persists only canonical non-secret reference summaries on the user event and the normal conversation context/tool-snapshot pipeline attaches the resulting project, Skill instructions, and tools to the Provider request.

## Non-goals

This change does not let a mention install, import, trust, globally enable, bind credentials, authorize, or directly execute a resource. It does not parse arbitrary `@text` into authority, switch an already bound conversation to another project, expand extension/MCP rows in the chooser, add a persistence schema, or expose MCP credentials, prompts, or resources.

## Impact

Renderer, Electron main/preload, and Go Core. `SubmitSessionMessage` gains an optional bounded `resourceReferences` field; application orchestration validates and applies it before event creation. The renderer invokes one narrow native local chooser from both `@` and `+`; dropped browser `File` objects are resolved by preload and inspected by Electron main. Their exact classified results are routed into the existing attachment or project flow. Existing project association and session activation stores are reused without a schema migration. Provider adapters, process lifecycle, and global resource configuration remain unchanged.

## Implementation constraints

The chooser must filter every source through its authoritative global enabled state. Only `source: builtin` catalog tools appear in the tool group; extensions and MCP servers appear once from their source records and are never expanded into contributed tools in the renderer. The single local action must use one narrow Electron-main-owned native chooser that accepts no renderer path, reads only the exact selected regular file up to 50 MB, returns a selected directory without reading its contents, and reuses the established attachment and project flows without adding a resource-reference kind. The composer `+` button must invoke this same action. For drag/drop, preload must derive paths only from actual dropped `File` objects and Electron main must independently require absolute non-symlink regular files or directories, cap each batch at 32 resources and 50 MB aggregate file content, and return no file path to the renderer. The first directory uses the single project-context slot and further directories are refused without blocking accepted files. The chooser must keep the controlled textarea caret stable after insertion, render fully above the composer at the same width as the composer card without a drop shadow and with a small visual gap, use the shared ScrollArea for bounded results, be keyboard accessible, and tolerate each catalog-read failure independently by retaining successful sources and existing projects.

The existing attachment flow must preserve exact valid UTF-8 text content, recognize authoritative model `attachment`/`attachments` capability metadata, and serialize supported binary files without silently dropping them from the Provider request. Core must reject malformed, ambiguous, unsupported-kind, negative-size, or over-50-MB attachment payloads before event persistence. Persisted event evidence remains metadata-only except for the existing image-preview behavior and must not add local paths or text/document bodies.

Core is authoritative: it accepts at most 32 deduplicated references, refuses unknown kinds, blank IDs, multiple distinct projects, disabled/stale resources, a project ID/path mismatch, conflicting project ownership, and queued delivery carrying references. Validation precedes user-event persistence. Applying a Skill/tool/source reference merges with rather than replaces existing conversation activation and cannot override global disablement. Repeated submission is idempotent for the same canonical reference. No migration applies; cancellation, timeout, dependency failure, and rollback use existing project/catalog/session error paths.

## Acceptance and evidence

- Happy path: `@` opens the chooser and selecting project, Skill, tool, extension, or MCP replaces the active query with a visible icon-and-name resource tag inside the editing region; immediate submit carries its typed identity and Core attaches the validated resource to the conversation.
- Boundary/refusal: an `@` inside a word does not open it; an empty filtered list has an explicit empty state; globally disabled resources and contributed extension/MCP tool rows are not shown.
- Keyboard: Arrow Up/Down follows the exact grouped display order, including the local file-or-folder action, without skipping entries, clamps at the first/last result, and scrolls the active row into the shared ScrollArea viewport; Enter performs the active result while the chooser is open and submits otherwise, Shift+Enter inserts a newline in both states, and Escape closes the chooser.
- Selected state: resource tags wrap within the composer, truncate long names, deduplicate exact resources, allow direct removal, remove the last tag when Backspace is pressed in an empty text input, and retain at most one draft project tag.
- Layout: the chooser is positioned relative to the full composer card with an explicit 4px offset above its outer top edge, matches its width, has no drop shadow, and uses a content-sized shared ScrollArea capped at 288px. Its viewport forbids horizontal overflow, while groups, rows, names, and descriptions shrink and truncate within the container at wide and narrow widths.
- Grouping: matching entries appear under stable local, project, Skill, extension, MCP, and tool headings; empty headings are omitted. The local group has one file-or-folder action that directly opens the native chooser; the composer `+` invokes the same callback. The returned kind enters the existing attachment or project-context flow, and the action is not submitted as a typed resource reference.
- Drag/drop: dropped regular files and directories are classified by Electron main through the same file-versus-directory router; all accepted files are attached, the first directory becomes project context, further directories produce an explicit refusal, and oversized, symbolic-link, non-regular, or excessive batches fail closed.
- Failure: catalog reads fail closed to the local project entry and do not block typing.
- Binding: a project selection creates or binds the conversation to that exact project without allowing later switching; Skill/tool/source activation merges with existing session state and remains idempotent.
- Security: handwritten text and forged/disabled/stale IDs have no effect; globally disabled tools cannot be reintroduced through a source reference; canonical event payloads exclude paths, credentials, schemas, prompt/resource bodies, and tool arguments.
- Delivery and failure: references are accepted only for immediate submission and validation failure occurs before the user event/turn; cancellation, timeout, and source readiness retain existing bounded behavior. Compatibility is additive and migration is N/A.

## Security and data lifecycle

Catalog responses already exposed to the renderer are filtered to enabled entries, but renderer state is untrusted and Core repeats validation at submit. The native local chooser accepts no renderer-authored path. For drag/drop, preload derives paths from actual dropped `File` objects and Electron main revalidates every path before returning a directory or reading bounded regular-file content. Neither path nor file content is logged. The existing session/project and activation metadata persist the binding; the user event stores only canonical kind, ID, and safe display name. No credential, tool schema, MCP prompt/resource content, raw selection payload, or new sensitive data is logged.

## Compatibility and migration

The request field is optional, so existing desktop clients and submissions remain compatible. No schema migration is required. Older clients cannot author structured mention bindings. The direct combined native file/directory chooser is supported on macOS; Electron's Windows/Linux native dialog becomes directory-only when both properties are requested, so equivalent behavior on those platforms remains pending platform-specific acceptance and design.
