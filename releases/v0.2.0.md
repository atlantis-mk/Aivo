# v0.2.0 Aivo Codex 原生能力与安全控制 / Codex-native capabilities and safer controls

Aivo v0.2.0 将 Codex 账户原生能力、动态模型工具声明和更清晰的本地权限控制带入桌面应用，同时让打包版 Core 为每次启动使用受控的动态回环端点。适合希望以 ChatGPT Codex OAuth 或已配置 Provider 在本机开展受控开发任务的用户升级。

Aivo v0.2.0 brings Codex account-native capabilities, dynamic model tool declarations, and clearer local permission controls to the desktop app. Packaged Core now uses an owned dynamic loopback endpoint per launch. It is for users running controlled local development tasks through ChatGPT Codex OAuth or configured Providers.

## 新增 / Highlights

- Codex OAuth 路由现在依据账户和模型声明安全启用受支持的网页搜索、图像生成与系统技能；API Key 路由仍保持独立，不能继承账户能力。
  The Codex OAuth route now safely enables supported web search, image generation, and system skills from account and model declarations. API-key routes remain separate and cannot inherit account capabilities.
- Provider 模型目录中的机器可读工具能力会自动同步；未知、过期、禁用或无效声明均会保持非授权状态。
  Machine-readable tool capabilities in Provider model catalogs now synchronize automatically. Unknown, stale, disabled, or invalid declarations remain non-authoritative.
- 默认工具集固定为本地编码基础能力以及 `update_plan`、`ask_user`；移除了自动批准模式，并为未来新建编码会话保存明确的默认权限模式。
  The default tool set now fixes local coding primitives alongside `update_plan` and `ask_user`; automatic approval is removed, and an explicit default permission mode is saved for future coding conversations.
- 内置与用户技能可以在桌面端管理；可选文件工具使用 `ls`、`find`、`grep` 的稳定名称，历史别名不会执行。
  Built-in and user skills can be managed from the desktop; optional file tools use stable `ls`, `find`, and `grep` names, and historical aliases are not executable.
- 安装版的 Core 使用操作系统分配的 IPv4 loopback 端口与受限 CSP，避免固定端口冲突和不受控的渲染器连接。
  Packaged Core uses an operating-system-assigned IPv4 loopback port and a restricted CSP, avoiding fixed-port conflicts and uncontrolled renderer connections.

### Compatibility and migration

This release migrates SQLite from schema v9 to v11. Before each v9-to-v10 and v10-to-v11 transition, Aivo creates or verifies a sanitized adjacent backup; an invalid or unavailable backup fails the migration before mutation. Existing rows default an empty assistant name to `Aivo` and a missing or invalid permission mode to `request_approval`. Existing conversations keep their own permission rules; changing the default affects only future coding conversations. Historical optional-tool selections under removed names no longer execute and must be reselected under `ls`, `find`, or `grep`. Downgrading to v0.1.2 after migration is unsupported; restore the verified pre-migration backup to roll back data.

### Known issues and compensation limits

The local macOS package is unsigned. Windows code signing and Linux distribution signing are not configured; target-platform macOS signing and notarization depend on repository secrets. R2 release objects are immutable, so a publication correction requires a new version. Automatic update remains explicit and digest-verified; it fails closed if the R2 manifest and GitHub release disagree.
