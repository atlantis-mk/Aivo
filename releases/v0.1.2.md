# v0.1.2 Aivo 桌面启动修复与全新图标 / Desktop Launch Fix and New Icon

Aivo v0.1.2 修复安装版应用在 `file://` 环境下可能出现的空白窗口和路由失效问题，并换用新的 Aivo 桌面图标。本版本适合所有 v0.1.0 和 v0.1.1 用户升级。

Aivo v0.1.2 fixes blank-window and navigation failures that could affect packaged apps under `file://`, and introduces the new Aivo desktop icon. All v0.1.0 and v0.1.1 users should upgrade.

## 新增 / Highlights

- 安装版现在使用相对资源路径，确保 HTML、脚本、样式、字体和图片从应用包内正确加载。
  Packaged builds now use relative asset paths so HTML, scripts, styles, fonts, and images load correctly from the application bundle.
- `file://` 环境改用 hash 路由，同时保留开发服务器的浏览器历史行为。
  The `file://` renderer now uses hash history while development servers retain browser history.
- 生产构建新增 bundle 完整性检查，绝对路径、缺失文件或越界引用会直接阻止构建。
  Production builds now fail on absolute, missing, or escaping local bundle references.
- 更新 Windows、macOS、Linux 应用图标及网页 favicon，并清理旧的重复生成目录。
  Refreshed Windows, macOS, Linux, and favicon artwork and removed the obsolete duplicated generated-icon directory.

## 安装提示 / Installation notes

本版本的 macOS 和 Windows 安装包尚未签名，Linux 分发签名也未配置。操作系统可能显示“无法验证开发者”、SmartScreen 或类似安全提示。请只从本仓库的正式 Release 下载，核对 SHA-256，并通过系统提供的用户确认流程继续；Aivo 不会绕过系统安全提示或静默安装。

The macOS and Windows packages are unsigned, and Linux distribution signing is not configured. Your operating system may show developer-verification or SmartScreen warnings. Download only from this official Release, verify SHA-256, and continue through the operating system's user-controlled approval flow; Aivo does not bypass security prompts or install silently.

### Known issues and compensation limits

The macOS and Windows packages are unsigned. macOS notarization and Windows code-signing evidence are unavailable, so users may receive operating-system trust warnings and this release must not be represented as a fully signed distribution. Linux distribution signing is also not configured. R2 objects under `aivo/releases/v0.1.2/` are immutable; correction requires a new version rather than replacement. Automatic update depends on both the public R2 stable manifest and the matching GitHub Release metadata; transient unavailability or disagreement fails closed and leaves the installed application unchanged.
